W11Basic Industrial Robot (3) — Inverse Kinematics

Forward vs inverse kinematics

Kinematics relates a robot's joint values to where its end effector (the tool at the tip) ends up.

Forward kinematics (FK)

Know the joint angles \(\theta_1 \dots \theta_6\) → find the pose \((X, Y, Z, R_x, R_y, R_z)\).

Inverse kinematics (IK)

Know the pose \((X, Y, Z, R_x, R_y, R_z)\) → find the joint angles \(\theta_1 \dots \theta_6\).

IK finds the joint variables that give a desired end-effector position and orientation — in the simple case, joint angles from given x and y.

  • The solution is difficult to find and not unique (several joint sets reach the same point).
  • Two analytical approaches: Geometric (triangles, law of cosines — used in class) and Algebraic.

2-link planar arm: finding θ₂ (law of cosines)

Link 1 has length \(a_1\) and joint angle \(\theta_1\) (from the x-axis). Link 2 has length \(a_2\) and angle \(\theta_2\) (relative to link 1). The target is \((x, y)\). Draw the line \(c\) from the base to the target, so \(c^2 = x^2 + y^2\).

  1. Law of cosines on the triangle \(a_1, a_2, c\): \(c^2 = a_1^2 + a_2^2 - 2a_1a_2\cos\theta_c\)
  2. Supplementary angle: \(\theta_c\) and \(\theta_2\) lie on a straight line, so \(\theta_c + \theta_2 = \pi\) and \(\cos\theta_c = -\cos\theta_2\).
  3. Substitute: \(c^2 = a_1^2 + a_2^2 + 2a_1a_2\cos\theta_2\)
$$\cos\theta_2 = \frac{x^2 + y^2 - a_1^2 - a_2^2}{2a_1a_2} = D$$

Then use Atan2 rather than \(\cos^{-1}\), so you keep both solutions and the correct quadrant:

$$\theta_2 = \operatorname{Atan2}\!\left(\pm\sqrt{1 - D^2},\; D\right)$$
\(D\) must be between −1 and 1. \(|D| > 1\) → the target is out of reach (no real solution). \(D = 1\) → arm fully stretched (\(\theta_2 = 0\)).

2-link planar arm: finding θ₁

  1. Angle of the line to the target: \(\omega = \operatorname{Atan2}(y, x)\)
  2. Angle between link 1 and that line (from link 2's geometry): \(\phi = \operatorname{Atan2}(a_2\sin\theta_2,\; a_1 + a_2\cos\theta_2)\)
  3. Combine: \(\theta_1 = \omega - \phi\)
$$\theta_1 = \operatorname{Atan2}(y, x) - \operatorname{Atan2}\big(a_2\sin\theta_2,\; a_1 + a_2\cos\theta_2\big)$$
Always solve θ₂ first, then plug each θ₂ into the θ₁ formula. Each sign of θ₂ gives its own θ₁.

The multiplicity of solutions (arm up / arm down)

The \(\pm\) in \(\theta_2 = \operatorname{Atan2}(\pm\sqrt{1-D^2}, D)\) gives two configurations that reach the same point: the elbow bends one way or the other.

Slide 12 pairs Arm Up with −√, but the Example 1 slides label θ₂ = +28.95° as "2nd Arm UP". Whether a sign means "up" depends on how the angle direction is drawn. For the exam, know that there are two solutions, one per sign, and draw both.
Value of DMeaning
\(|D| < 1\)Two solutions (θ₂ = ±)
\(D = \pm 1\)One solution — arm fully stretched (θ₂ = 0) or fully folded (θ₂ = 180°)
\(|D| > 1\)No solution — target outside the workspace

Why Atan2 instead of standard tan⁻¹?

\(\tan\theta = y/x\) loses quadrant information: \((+,+)\) in quadrant I and \((-,-)\) in quadrant III give the same positive ratio. \(\operatorname{Atan2}(y, x)\) looks at the signs of both arguments, so the robot identifies the correct physical quadrant of the target.

Point (x, y)tan⁻¹(y/x)Atan2(y, x)
(3, 3)45°45°
(−3, 3)−45° ✗135°
(−3, −3)45° ✗−135° (= 225°)
(3, −3)−45°−45°
Argument order is Atan2(y, x) — the "opposite" side first, then the "adjacent" side.

Worked example (lecture Example 1)

\(a_1 = 3\), \(a_2 = 5\), target \((x, y) = (2.0,\ 7.5)\). Find all \(\theta_1, \theta_2\).

$$D = \frac{7.5^2 + 2^2 - 3^2 - 5^2}{2(3)(5)} = \frac{26.25}{30} = 0.875 \qquad \sqrt{1 - D^2} = 0.484$$ $$\theta_2 = \operatorname{Atan2}(\pm 0.484,\ 0.875) = \pm 28.96^\circ$$

Now \(\theta_1\), with \(\operatorname{Atan2}(7.5, 2) = 75.07^\circ\) and \(\phi = \operatorname{Atan2}(5\sin\theta_2,\ 3 + 5\cos\theta_2) = \pm 18.17^\circ\):

θ₂θ₁ = 75.07° − φCheck (FK)
+28.96°56.90°x = 2.00, y = 7.50 ✓
−28.96°93.24°x = 2.00, y = 7.50 ✓
Slides 24–25 evaluate Atan2(7.5, 2) as 14.93°, which is really Atan2(2, 7.5) (x and y swapped). That gives θ₁ = −3.24° and 33.10°, which reach the mirrored point (7.5, 2). With Atan2(y, x) = 75.07°, the correct answers for (2, 7.5) are 56.90° and 93.24°. D and θ₂ on the slides are correct.

RRR configuration (no offset) — 2D projected into 3D

An RRR (Revolute-Revolute-Revolute) robot in 3D is mathematically identical to a 2-link planar robot, just rotating on a base axis. Swap the planar coordinates:

base x → projected radius rbase y → vertical height s
$$\theta_1 = \operatorname{Atan2}(y_c, x_c) \qquad r = \sqrt{x_c^2 + y_c^2} \qquad s = z_c - d_1$$ $$D = \frac{r^2 + s^2 - a_2^2 - a_3^2}{2a_2a_3} = \frac{x_c^2 + y_c^2 + (z_c - d_1)^2 - a_2^2 - a_3^2}{2a_2a_3}$$ $$\theta_3 = \operatorname{Atan2}\!\left(\pm\sqrt{1 - D^2},\ D\right)$$ $$\theta_2 = \operatorname{Atan2}\!\left(z_c - d_1,\ \sqrt{x_c^2 + y_c^2}\right) - \operatorname{Atan2}\big(a_3\sin\theta_3,\ a_2 + a_3\cos\theta_3\big)$$

Another valid base solution is \(\theta_1 = \operatorname{Atan2}(y_c, x_c) + \pi\) (reaching back over the base).

Slide 16 prints \(a_3^3\) in D. It should be \(a_3^2\). Slide 27 labels the links \(a_1, a_2\) in the D formula but \(a_2, a_3\) in the figure — use the links that form the elbow (\(a_2, a_3\)). Slide 27 also shows the θ₂ subtraction term with its arguments swapped (\(a_2 + a_3\cos\theta_3\) first). The order above, \(\operatorname{Atan2}(a_3\sin\theta_3,\ a_2 + a_3\cos\theta_3)\), matches the 2-link θ₁ formula.

Example: \(d_1 = 1\), \(a_2 = 4\), \(a_3 = 3\), target (3, 4, 2) → θ₁ = 53.13°, r = 5, s = 1, D = 0.0417, θ₃ = ±87.61°.

RRR with offset — the offset illusion

When the shoulder is offset sideways by \(d\), the arm plane no longer passes through the base axis. The same target can then be reached with the elbow bending to either side of the target line:

Left-arm configuration

Elbow bends left of the target line.

Right-arm configuration

Elbow bends right of the target line.

By Pythagoras, the usable in-plane radius shrinks to \(\sqrt{x_c^2 + y_c^2 - d^2}\). The θ₁ "modifier" formulas:

$$\text{Right arm: }\ \theta_1 = \operatorname{Atan2}(y_c, x_c) + \operatorname{Atan2}\!\left(-\sqrt{x_c^2 + y_c^2 - d^2},\ -d\right)$$ $$\text{Left arm: }\ \theta_1 = \operatorname{Atan2}(y_c, x_c) - \operatorname{Atan2}\!\left(\sqrt{x_c^2 + y_c^2 - d^2},\ d\right)$$

Right arm derivation: \(\theta_1 = \alpha + \beta\), with \(\alpha = \operatorname{Atan2}(y_c, x_c)\), \(\gamma = \operatorname{Atan2}(\sqrt{r^2 - d^2}, d)\) and \(\beta = \gamma + \pi\). Since \(\cos(\theta+\pi) = -\cos\theta\) and \(\sin(\theta+\pi) = -\sin\theta\), \(\beta = \operatorname{Atan2}(-\sqrt{r^2-d^2}, -d)\).
Left arm: \(\theta_1 = \phi - \alpha\), where \(\phi = \operatorname{Atan2}(y_c, x_c)\) and \(\alpha = \operatorname{Atan2}(\sqrt{r^2-d^2}, d)\).

For θ₂ and θ₃ use the RRR formulas, but with \(r^2 = x_c^2 + y_c^2 - d^2\):

$$D = \frac{x_c^2 + y_c^2 - d^2 + (z_c - d_1)^2 - a_2^2 - a_3^2}{2a_2a_3} \qquad \theta_3 = \operatorname{Atan2}\!\left(\pm\sqrt{1 - D^2},\ D\right)$$ $$\theta_2 = \operatorname{Atan2}\!\left(z_c - d_1,\ \sqrt{x_c^2 + y_c^2 - d^2}\right) - \operatorname{Atan2}\big(a_3\sin\theta_3,\ a_2 + a_3\cos\theta_3\big)$$
Slide 29 reverses the arguments of every Atan2: θ₃ = Atan2(D, ±√(1−D²)), and θ₂ = Atan2(√(x²+y²−d²), z−d₁) − Atan2(a₂+a₃cosθ₃, a₃sinθ₃). Slide 31 also ends with "−d₁" where it should be "−d". Use the Atan2(y, x) order shown above, which matches slides 12, 13, 14 and 18.

RRP configuration (Revolute-Revolute-Prismatic)

Replacing the last rotating joint with an extending (prismatic) joint vastly simplifies IK.

RRRRRP

ComplexityHigh — law of cosinesLow — Pythagorean theorem
$$\theta_1 = \operatorname{Atan2}(y_c, x_c) \qquad r = \sqrt{x_c^2 + y_c^2} \qquad s = z_c - d_1$$ $$d_3 = \sqrt{r^2 + s^2} = \sqrt{x_c^2 + y_c^2 + (z_c - d_1)^2}$$ $$\theta_2 = \operatorname{Atan2}(s, r) = \operatorname{Atan2}\!\left(z_c - d_1,\ \sqrt{x_c^2 + y_c^2}\right)$$

W13Sensor and Smart Device

What is a sensor?

A sensor is a device that detects physical changes and converts them into electrical signals.
  • Detects phenomena such as temperature, light, pressure and chemical substances.
  • Used in industrial automation, environmental monitoring, consumer electronics and medical devices.
  • Gives systems the data to monitor, analyze and interact with their surroundings.
  • Types: electronic, mechanical, optical, chemical, biological and thermal. Each detects specific properties and converts them into measurable signals.
SensorWhat it does
Temperature sensorDetects temperature changes → electrical signal
Pressure sensorGas/liquid pressure → proportional electrical signal
Load cellForce or weight → signal, via mechanical deformation
Photoelectric sensorUses light to detect presence, absence or position
EncoderRotational or linear motion → digital or analog signal
Safety light curtainMultiple light beams detect intrusion, for safety

How a sensor works — 4 stages

1 Detection→2 Conversion (transduction)→3 Signal conditioning→4 Output
  1. Detection of physical phenomenon — a sensing element interacts directly with the quantity (temperature, light, pressure, displacement) and changes.
  2. Conversion (transduction) — the change becomes an electrical signal. At this stage it is weak, analog and not yet usable.
  3. Signal conditioning — improve quality and reliability: amplification, filtering, linearization, noise reduction.
  4. Output — an analog or digital signal read by a PLC, microcontroller, DAQ system, or display.

Smart sensors

A smart sensor is a sensor with built-in signal processing, intelligence, and communication capabilities.

It takes input from the environment and uses built-in compute to perform predefined functions, processing data before passing it on. The result is more accurate, automated data with less noise. Uses include smart grids, reconnaissance, exploration and science.

FunctionDescription
MeasurementMeasures physical quantities (detect → electrical signal)
ConfigurationSetup and calibration; detects position or installation errors
VerificationSelf-diagnostics — nonstop supervision of sensor behavior
CommunicationExchanges data with the main microcontroller or external devices

Benefits: high accuracy, real-time monitoring, self-diagnostics, digital communication, easy Industry 4.0 integration.

Applications: motion sensors (occupancy → lights on/off, saves energy), light sensors (daylight harvesting, human-centric lighting), thermal sensors (HVAC, equipment overheating), smoke sensors (early fire alarm, more evacuation time).

Smart sensor block diagram

Sensing unit→Signal conditioning→ADC→Application algorithms⇄Communication unit
  • Sensing unit — detects changes in physical parameters and produces equivalent electrical signals.
  • Signal conditioning unit — shapes the signal for the next stage without losing data.
  • ADC — converts analog to digital and sends it to the microprocessor.
  • Application algorithm — processes data with the loaded program and generates output signals.
  • Memory — stores received and processed data.
  • Local user interface (LUI) — panel-mounted device that lets building operators monitor and control equipment.
  • Communication unit / transceiver — sends outputs to the main station and receives commands from it.

The impact of sensors on industrial automation

Sensors provide real-time data, measure key parameters (temperature, pressure, flow rate, vibration), and enable automatic control and optimization.

  1. Real-time monitoring & process control
  2. Fault detection & predictive maintenance — catch abnormal conditions before failure
  3. Quality improvement — fewer defects
  4. Energy efficiency — lower operating cost
  5. Safety enhancement — detect hazards, fewer accidents

Benefits of integration: improved efficiency (less downtime), increased productivity, enhanced quality, reduced costs (energy, waste, maintenance), improved safety.

W14Smart Device and Interface System — Node-RED

What is an interface?

An interface is a connection point that allows two systems or devices to exchange information.
Connect→Exchange data→Work together
LinkInterface examples
Sensor → PLCDigital I/O (24 VDC), analog I/O (0–10 V), current (4–20 mA), temperature (RTD, thermocouple), proximity/photoelectric
PLC (FX5U) itselfDigital I/O, analog I/O, high-speed counter, pulse output, positioning/motion control
PLC → dashboard / HMIEthernet (TCP/IP), serial (RS-232 / RS-485), industrial networks (CC-Link IE), USB, OPC / MQTT / Web API

Types of interface — and why we need one

1 · Hardware interface — connects devices

The physical and electrical connection for transferring signals or data.

  • External ports: USB, HDMI, Ethernet
  • Internal slots: PCIe (graphics card, memory)
  • Chip protocols: UART, SPI

2 · Software interface — connects applications & data

Lets different software or systems exchange and process data.

  • UI: GUI (icons, windows) and CLI (typed text)
  • API: software systems talk to each other
  • Programming/object interface: a code contract — what a component must do, not how

Question from the slide: "If we connect a PLC and a computer using an Ethernet cable, can they communicate immediately?" — No. The cable is only the hardware interface. Both sides also need matching network settings and a common protocol (see interface vs protocol).

Why? We need an interface / integration solution to collect, process and deliver PLC data to other systems: dashboards (live data, trends, KPIs), databases (history, reporting, analytics), IoT/MQTT (device communication, edge computing) and cloud (storage, analytics, remote access).

What is Node-RED?

Node-RED is a flow-based programming tool for connecting devices, systems and online services. It is not a communication protocol — it is an integration tool that works with different protocols.
  • Goal: let anyone build applications that collect, transform and visualize data. It is low-code, so it suits users of any background.
  • Built on Node.js (event-driven, non-blocking) → runs at the edge on low-cost hardware (Raspberry Pi) and in the cloud.
  • Installation (W13): install Node.js → run the Node-RED install command → verify the installation → run Node-RED.

How does Node-RED work? Input → Process → Output:

StageNodeExample
Input — data enters the flowInjectSimulated sensor value (temperature = 35 °C)
Process — transform / filterFunctionConvert units, calculate, format, add timestamp

Your first flow: Inject → Debug

  1. Open the editor: http://localhost:1880 (from another computer: http://<ip-address>:1880).
  2. Add an Inject node — injects messages by clicking its button or on a time interval.
  3. Add a Debug node — shows messages in the Debug sidebar (by default only msg.payload; it can show the whole message).
  4. Wire them — drag from the output port of one to the input port of the other.
  5. Deploy — nodes only exist in the editor until you click Deploy.
  6. Inject — click the Inject button. Numbers appear: by default the payload is a timestamp in milliseconds.

Editor layout — 4 components

  1. Header (top) — Deploy button, main menu, user menu (if authentication is enabled).
  2. Palette (left) — the nodes available to use, in categories (inputs, outputs, functions first; subflows at the top). Can be hidden.
  3. Workspace (middle) — build flows by dragging nodes and wiring them. It has one tab per flow/subflow. The footer has zoom in/out/reset and the view navigator (scaled-down map for finding "lost" nodes). Customize it via User Settings → View.
  4. Sidebar (right) — info, debug, config nodes, context.

Flows, nodes & wires

Flow = a tab in the workspace, the main way to organize nodes. (Informally, "flow" also means one set of connected nodes, so one tab can contain several flows.)

  • Each flow has a name and description (shown in the Info sidebar); all nodes in a flow share flow-scoped context.
  • Add a flow: the + button, or double-click free space in the tab bar. Reorder by dragging tabs.
  • Edit flow properties: double-click its tab → Properties (name, Markdown description) and Environment Variables.
  • Disabled flow: none of its nodes are created on deploy.

Adding nodes: drag from the palette, use the Quick-Add dialog (Ctrl/Cmd + click the workspace), or import from the library/clipboard.

  • A node has at most one input port and many output ports. Ports can have labels (e.g. a Switch node shows the matching rule).
  • Status under a node shows its runtime state (e.g. MQTT connected).
  • Blue circle = undeployed changes · red triangle = configuration errors.
  • Inject and Debug are the only core nodes with buttons.
  • Edit a node: double-click or press Enter (with several selected, the first is edited). Tabs: Properties, Description, Appearance.

Wires: press on a port, drag to the destination, release. Or hold Ctrl/Cmd, click the port, then click the destination; keep holding to chain more wires quickly.

Arranging: the Arrange menu aligns and distributes nodes, e.g. align left Alt-a l, right Alt-a r, top Alt-a t, bottom Alt-a b, middle Alt-a m, center Alt-a c, distribute horizontally Alt-a h, vertically Alt-a v.

Groups & subflows

Group

Nodes joined so they move/copy as one object. Can have a border, background color and label. Create: select nodes → Groups → Group selection. Edit: double-click (Properties, Environment Variables, Description).

Subflow

A collection of nodes collapsed into a single node. It reduces visual complexity and packages reusable logic. Once created, it appears in the palette.

  • Create empty: Subflow → Create subflow. Convert: Subflow → Selection to Subflow.
  • Conversion is only possible if the wires coming into the selection connect to one node — a subflow node has at most one input.
  • Edit it by double-clicking it in the palette, or with "Edit flow template" in an instance. Subflow tabs can be closed (unlike flow tabs).
  • Inputs/outputs are grey square nodes: at most one input, as many outputs as needed. There is an optional status output (msg.payload = string or Status Object).
  • Properties dialog tabs: Properties (per-instance env vars), Module Properties (metadata), Description, Appearance.

FX5U setting for SLMP (GX Works3)

  1. Navigation → Parameter → FX5UCPU → Module Parameter → Ethernet Port.
  2. Basic Settings → Own Node Settings: IP address 192.168.3.36, subnet mask 255.255.255.0. (Communication data code: Binary.)
  3. External Device Configuration → <Detailed Setting> opens the Ethernet Configuration window.
  4. From Module List → Ethernet Device (General), drag in an SLMP Connection Module. Set protocol TCP and port 9000.
  5. Click Close with Reflecting the Setting, then Check and Apply. Write the parameters to the PLC.

Node-RED: MC protocol nodes

Install node-red-contrib-mcprotocol (v1.2.1, 3 nodes). The MITSUBISHI palette category then shows MC Read, MC Write, Ind MC Read and Ind MC Write.

  • MC Write node: Connection (192.168.3.36:9000), Address (e.g. M100), Data (msg.payload), Errors (Throw).
  • MC Protocol Connection: Host 192.168.3.36, Port 9000, frame 3E, protocol TCP, PLC type Q, PC No 0xff, timeout 1000 ms.
The host IP and port in Node-RED must match the FX5U's Own Node IP and the SLMP module's port.

Interface vs protocol

Devices need both a physical/logical connection (interface) and a common language (protocol).

Interface — how devices are connected

  • Physical or logical connection
  • Electrical signals, connectors, cables, network media
  • Examples: Ethernet (RJ45), serial RS-232 / RS-485, USB, Wi-Fi
  • Different interfaces can use the same protocol

Protocol — how data is communicated

  • Rules for how data is formatted, transmitted and interpreted
  • The "language" devices use to understand each other
  • Examples: Modbus, PROFINET, EtherNet/IP, OPC UA, MQTT
  • Different protocols can run over the same interface

Modbus: client-server, request-response

Modbus is a widely used industrial protocol for data exchange between PLCs, HMIs, sensors, inverters, robots, PCs and Node-RED.

  • The client (HMI, SCADA, PC, Node-RED) sends a request to read/write data.
  • The server (PLC, device) processes it and returns a response.
  • Only the client can start communication.
  • Example: request "Read Holding Register, address 0, quantity 1" → response "Data: 1500".
